# 💎 Diamond Price & Market Segment Predictor (Streamlit)

## Files
- `app.py` — the Streamlit application
- `pipeline.pkl` — StandardScaler + XGBRegressor pipeline (price regression), from notebook cell 33
- `encoder.pkl` — OrdinalEncoder fitted on `cut`/`color`/`clarity`, from notebook cell 20
- `cluster_model.pkl` — KMeans (k=3), from notebook cell 30
- `cluster_scaler.pkl` — StandardScaler used before KMeans, from notebook cell 30

All four `.pkl` files were regenerated by re-running the notebook's exact
preprocessing/training steps against the public `diamonds` dataset, since the
notebook itself doesn't save its intermediate `df` — only the models. If you
retrain from your own `diamonds.csv`, just re-run the notebook's save cells
(28, 30, 33) and drop the new `.pkl` files next to `app.py`.

## Run locally
```bash
pip install -r requirements.txt
streamlit run app.py
```
Then open the local URL Streamlit prints (usually http://localhost:8501).

## How it works
1. **Shared input form**: carat, x, y, z (numeric), cut/color/clarity (dropdowns).
   Depth and table are also collected — the trained models require all 9
   features (`carat, cut, color, clarity, depth, table, x, y, z`), so these two
   were added even though the original spec only listed carat/x/y/z.
2. **Preprocessing reproduced exactly as in the notebook**: `carat`, `x`, `y`,
   `z` are square-root transformed before being fed to the models (the
   notebook applied `np.sqrt` to fix skew), and `cut`/`color`/`clarity` are
   ordinal-encoded using the saved `encoder.pkl`.
3. **Predict Price** → `pipeline.predict()` returns `sqrt(price_usd)`; the app
   squares it to get USD, then multiplies by 83 (same rate used in the
   notebook) to display **INR**.
4. **Predict Cluster** → the same preprocessed row is scaled with
   `cluster_scaler.pkl` and passed to `cluster_model.pkl`. The numeric cluster
   ID is mapped to a human-readable name based on each cluster's actual
   average carat/price in the training data:
   - Cluster 0 → **Premium Heavy Diamonds** (avg ≈1.5 ct, avg ≈$9.7k)
   - Cluster 1 → **Affordable Small Diamonds** (avg ≈0.4 ct, avg ≈$1.0k)
   - Cluster 2 → **Mid-Range Diamonds** (avg ≈0.9 ct, avg ≈$4.3k)

   If you retrain KMeans, re-check `CLUSTER_NAMES` in `app.py` — cluster index
   assignment can change between runs.
